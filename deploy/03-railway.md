# ۳ — استقرار روی Railway

## چه لازم داری
- یک حساب GitHub و یک حساب Railway.
- پوشه `proxy-minimal` را در یک ریپوی GitHub بگذار (ریپو باید `proxy.py` و
  `Dockerfile` و `requirements.txt` را در ریشه داشته باشد).

## قدم‌ها

### ۱) پروژه بساز
1. وارد Railway شو → **New Project**.
2. **Deploy from GitHub Repo** را انتخاب کن و ریپو را انتخاب کن.
3. Railway خودش Dockerfile را پیدا می‌کند و بیلد می‌کند؛ تنظیم دیگری لازم نیست.

### ۲) فقط یک متغیر محیطی ست کن
در سرویس، بخش **Variables**:

```
TARGET_BASE_URL=https://آدرس-مقصد-خودت
```

پورت را Railway خودش با `PORT` ست می‌کند و Dockerfile همین را می‌خواند.

### ۳) دامنه عمومی بگیر
1. در سرویس، بخش **Settings** → قسمت **Networking** → **Generate Domain** را بزن.
2. آدرسی شبیه `https://نام-سرویس.up.railway.app` می‌گیری.

### ۴) تست
اول سلامت:
```
https://نام-سرویس.up.railway.app/health
```
بعد یک مسیر واقعی، مثلاً `/v1/models` — باید جواب مقصد برگردد.

## نکات مهم
- **هزینه:** Railway اعتبار آزمایشی می‌دهد و بعد از آن مصرفی (pay-as-you-go)
  حساب می‌شود؛ پلن رایگان دائمی ندارد. قبل از دیپلوی، قیمت و اعتبار
  همان صفحه را چک کن.
- **تغییر مقصد:** فقط مقدار `TARGET_BASE_URL` را در Variables عوض کن؛
  سرویس خودش دوباره Deploy می‌شود.
- **به‌روزرسانی کد:** هر push جدید به branch، خودش دوباره Deploy می‌شود.
- **لاگ:** اگر سرویسی بالا نیامد، اول **Deployments** → **View Logs** را ببین؛
  معمولاً خطا همان‌جا نوشته شده (مثلاً `TARGET_BASE_URL` ست نشده).
