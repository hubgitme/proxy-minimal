# ۲ — استقرار روی Koyeb (پیشنهاد اول برای جایگزین)

## چه لازم داری
- یک حساب GitHub و یک حساب Koyeb.
- پوشه `proxy-minimal` را در یک ریپوی GitHub بگذار (public یا private؛
  ریپو باید `proxy.py` و `Dockerfile` و `requirements.txt` را در ریشه داشته باشد).

## قدم‌ها

### ۱) ریپو را آماده کن
فایل‌های پوشه `proxy-minimal` را در ریپو بگذار و push کن.
فایل `.env` را به ریپو نفرست؛ فقط `.env.example` باشد.

### ۲) در Koyeb سرویس بساز
1. وارد Koyeb شو → **Create App**.
2. منبع را **GitHub** انتخاب کن و ریپو و branch را انتخاب کن.
3. **Builder** را **Dockerfile** بگذار (مسیر Dockerfile را ریشه بگذار).
4. **Port** را `8000` بگذار.
5. **Instance type** را **Free** انتخاب کن.

### ۳) فقط یک متغیر محیطی ست کن
در بخش **Environment variables** همان سرویس:

```
TARGET_BASE_URL=https://آدرس-مقصد-خودت
```

چیز دیگری لازم نیست. پورت را Koyeb خودش با `PORT` ست می‌کند و Dockerfile
همین را می‌خواند.

### ۴) Deploy و تست
- **Deploy** را بزن و صبر کن تا وضعیت Running شود.
- آدرس سرویس چیزی شبیه این می‌شود: `https://نام-سرویس-نام-سازمان.koyeb.app`
- اول تست سلامت:
  ```
  https://نام-سرویس-نام-سازمان.koyeb.app/health
  ```
- بعد یک مسیر واقعی، مثلاً `/v1/models` — باید جواب مقصد برگردد.

## نکات مهم
- **پلن رایگان (Starter):** یک سرویس با ۵۱۲ مگابایت RAM و 0.1 vCPU، فقط در
  Frankfurt یا Washington.
- **خوابیدن:** بعد از یک ساعت بی‌کاری سرویس خاموش می‌شود و اولین درخواست
  بعدی دیر جواب می‌دهد (cold start). برای تست و استفاده سبک مشکلی نیست؛
  برای استفاده دائمی و فوری، VPS (فایل ۰۵) بهتر است.
- **کارت بانکی:** منابع جدید می‌گویند موقع ثبت‌نام کارت می‌خواهد (با هولد
  ۲۹ دلاری)؛ راهنماهای قدیمی‌تر می‌گفتند نمی‌خواهد. موقع ثبت‌نام خودش
  مشخص می‌شود — قبل از وارد کردن کارت، شرایط همان صفحه را بخوان.
- **تغییر مقصد:** هر وقت خواستی آدرس را عوض کنی، فقط مقدار
  `TARGET_BASE_URL` را در همان سرویس عوض کن و Redeploy بزن؛ کد عوض نمی‌شود.
- **به‌روزرسانی کد:** هر push جدید به branch، در Koyeb خودش دوباره Deploy می‌شود.
